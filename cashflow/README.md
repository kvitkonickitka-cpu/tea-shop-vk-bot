# Учёт денег: выписка Т-Бизнеса → PostgreSQL → DataLens

Ежедневно забирает операции по счетам Т-Бизнеса, раскладывает их по статьям
движения денег и считает FCF, runway и прочие метрики. Дашборд собирается
в Yandex DataLens.

## Что важно знать сразу

- Всё живёт в **отдельной схеме `finance`**. Таблицы магазина и данные клиентов
  не читаются и не изменяются.
- Банк используется **только на чтение**: токен выпускается с доступом
  «Счета и выписки», методов платежей в коде нет.
- Классификация **детерминированная**: правила, которые вы задали, и ничего больше.
  Что не совпало — честно попадает в «Не разобрано», а не угадывается.
- Секреты лежат в `/etc/cashflow/.env` с правами 600 и в репозиторий не попадают.

## Как устроено

```
Т-Банк T-API ──(ежедневно в 07:00, systemd timer, статический IP ВМ)──► cashflow
                                                                          │
PostgreSQL на ВМ                                                          ▼
 ├── схемы магазина (заказы, клиенты)   ← не трогаем
 └── finance
      ├── raw_operations, balances, sync_state   сырьё из банка
      ├── articles, rules, manual_overrides,     справочники (из CSV)
      │   loan_schedule, settings
      ├── fact_operations                        результат классификации
      └── v_cash_summary, v_metrics, v_ddc,      витрины — только их видит DataLens
          v_unclassified, v_channel_mix
```

Порядок классификации: **ручная разметка → правила по приоритету (первое
совпадение) → «Не разобрано»**.

Особые случаи:

- платёж по кредиту приходит одной суммой и делится по графику: проценты в CFO,
  тело долга в CFF;
- ЕНП — одна статья, без разбивки по налогам;
- переводы между своими счетами — технические, в отчёты о прибыли не попадают;
- переводы на личные карты партнёров — вывод собственнику, пополнения с них — взнос.

## Команды

```bash
python -m cashflow doctor          # проверить сертификаты, IP, токен, базу, свежесть данных
python -m cashflow migrate         # применить миграции схемы finance
python -m cashflow import-rules    # загрузить справочники из data/*.csv
python -m cashflow sync            # забрать свежие операции (перекрытие 10 дней)
python -m cashflow backfill --from 2024-01-01   # полная загрузка истории
python -m cashflow classify        # разложить по статьям
python -m cashflow suggest-rules   # черновик правил по неразобранному
python -m cashflow run-all         # import-rules + sync + classify (так работает таймер)
python -m cashflow loan-schedule --amount 100000 --rate 27 --months 12 \
                   --first-payment 2025-02-10   # посчитать аннуитет
```

## Справочники

Редактируются как обычные таблицы в `data/`, потом загружаются командой `import-rules`:

- `articles.csv` — статьи движения денег;
- `rules.csv` — правила классификации;
- `manual_overrides.csv` — ручная разметка отдельных операций;
- `loan_schedule.csv` — график платежей по кредиту.

Если в файле ошибка, загрузка отменяется целиком и в базе остаются прежние значения.

## Разработка и тесты

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"     # через -e, иначе не найдутся migrations/ и data/
.venv/bin/python -m pytest            # тесты логики, база не нужна
```

Тесты на настоящей базе (сходимость денег, идемпотентность, права DataLens)
запускаются против **отдельной** базы, в имени которой есть `test`:

```bash
createdb finance_test
psql -d finance_test -v sync_password=... -v ro_password=... -f migrations/001_schema_and_roles.sql
CASHFLOW_TEST_DSN="host=127.0.0.1 dbname=finance_test user=finance_sync password=..." \
CASHFLOW_TEST_DSN_RO="host=127.0.0.1 dbname=finance_test user=datalens_ro password=..." \
  .venv/bin/python -m pytest tests/test_integration_db.py
```

## Что проверяется перед тем, как верить цифрам

- `check_diff = 0` в каждом месяце: остаток на конец минус остаток на начало
  равен движению денег;
- поток за квартал и год равен сумме месячных, а остаток берётся на последний
  день периода, а не суммируется;
- повторный запуск не меняет ни количество операций, ни суммы;
- доля «Не разобрано» меньше 5% по сумме;
- роль `datalens_ro` не может прочитать ничего, кроме витрин.

## Чего здесь намеренно нет

- Интеграции с API ЮKassa и Ozon: выплаты видны в выписке нетто.
  Сверка брутто-заказов с выплатами — следующий этап (`v_acquiring_recon`).
- Вебхуков банка: источник правды — `GET /api/v1/statement`.
- Языковых моделей в конвейере: подсказки для «Не разобрано» возможны позже,
  но только как предложение, применяемое после подтверждения человеком.
