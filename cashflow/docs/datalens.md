# Подключение Yandex DataLens и сборка дашборда

DataLens будет ходить в базу под ролью `datalens_ro`, которая видит **только витрины**
и не может прочитать ни сырые операции, ни таблицы магазина. Это проверяется тестом.

## Часть 1. Открыть базу для DataLens

База стоит на обычной ВМ, а не в Managed PostgreSQL, поэтому галочки «Доступ из
DataLens» нет — нужно открыть порт вручную, и только для адресов DataLens.

### 1.1. Разрешить подключения по сети

**Если база в Docker** (проверяется командой `docker ps`), этот подраздел пропускайте:
официальный образ `postgres` уже слушает все адреса внутри контейнера и принимает
пароли по `scram-sha-256`. Наружу порт отдаёт сам Docker — тем пробросом, что виден
в `docker ps` как `0.0.0.0:5432->5432/tcp`. Настраивайте только группу безопасности
(подраздел 1.2), а `postgresql.conf` и `pg_hba.conf` не трогайте: они лежат внутри
контейнера и при его пересоздании обнулятся.

**Если база установлена на саму машину** — посмотрите, слушает ли она внешние адреса:

```bash
sudo -u postgres psql -c "SHOW listen_addresses;"
```

Если ответ `localhost`, нужно изменить. **Сначала сделайте копию файлов:**

```bash
sudo cp /etc/postgresql/*/main/postgresql.conf ~/postgresql.conf.backup
sudo cp /etc/postgresql/*/main/pg_hba.conf ~/pg_hba.conf.backup
```

Затем в `postgresql.conf`:

```
listen_addresses = '*'
ssl = on
```

В `pg_hba.conf` добавьте строку **на каждый диапазон адресов DataLens** — только
для роли `datalens_ro`, только к вашей базе и только по защищённому соединению:

```
# TYPE  DATABASE      USER          ADDRESS              METHOD
hostssl ИМЯ_БАЗЫ      datalens_ro   ДИАПАЗОН_DATALENS    scram-sha-256
```

Актуальный список диапазонов IP-адресов DataLens есть в документации Yandex Cloud
в разделе про подключение к базам вне облака. Вписывать `0.0.0.0/0` нельзя — это
открывает базу всему интернету.

Применить:

```bash
sudo systemctl reload postgresql
```

### 1.2. Группа безопасности ВМ

В консоли Yandex Cloud: Virtual Private Cloud → Группы безопасности → группа вашей ВМ.
Добавьте входящее правило: порт `5432`, протокол TCP, источник — те же диапазоны
DataLens. Одно правило на каждый диапазон.

### 1.3. Проверка изоляции

Убедитесь, что роль для DataLens действительно ничего лишнего не видит:

```bash
PGPASSWORD=ПАРОЛЬ psql -h localhost -U datalens_ro -d ИМЯ_БАЗЫ \
  -c "SELECT count(*) FROM finance.raw_operations;"
```

Правильный ответ — ошибка «permission denied». А это должно работать:

```bash
PGPASSWORD=ПАРОЛЬ psql -h localhost -U datalens_ro -d ИМЯ_БАЗЫ \
  -c "SELECT * FROM finance.v_cash_summary LIMIT 5;"
```

## Часть 2. Подключение в DataLens

1. Откройте DataLens → Подключения → Создать подключение → PostgreSQL.
2. Заполните:
   - Хост — статический IP вашей ВМ;
   - Порт — 5432;
   - Имя базы — ваша база;
   - Логин — `datalens_ro`, пароль — тот, что задали при создании роли;
   - SSL — включить.
3. Нажмите «Проверить подключение», затем «Создать».

## Часть 3. Датасеты

Создайте четыре датасета на этом подключении — по одному на витрину:

| Датасет | Таблица | Для чего |
|---|---|---|
| Денежный поток | `finance.v_cash_summary` | остатки, CFO, FCF, FCFE, проверка сходимости |
| Метрики | `finance.v_metrics` | маржа, runway, DSCR, доли |
| ДДС | `finance.v_ddc` | таблица «статья × месяц» |
| Не разобрано | `finance.v_unclassified` | что требует внимания |

В датасете «Денежный поток» сделайте `period_start` измерением типа «Дата»,
а денежные колонки — показателями с типом «Дробное число».

## Часть 4. Чарты

Соберите на датасете **Денежный поток**:

1. **Индикаторы (KPI).** Четыре штуки: `closing_balance` («Денег на счетах»),
   `fcf` («Свободный поток за месяц»), `cfo` («Операционный поток»),
   и с датасета «Метрики» — `runway_months` («На сколько хватит денег, мес.»).
   В каждом поставьте фильтр `period_type = M` и сортировку по `period_start` по убыванию.

2. **Столбчатая диаграмма «FCF по месяцам».** X — `period_start`, Y — `fcf`.
   Добавьте вторую линию `fcf_rolling_3m` — это сглаженный поток за три месяца,
   по нему видно тенденцию, а не случайные скачки одного месяца.

3. **Водопад «Из чего сложился поток».** X — категории, Y — суммы:
   `cfo` → `capex` → `loan_in` → `loan_principal_out` → `fcfe`. Если водопада нет
   в списке типов, подойдёт столбчатая диаграмма с этими же полями.

4. **Структура расходов.** Датасет ДДС, фильтр `section = CFO` и `amount < 0`.
   X — `period_start`, Y — `amount`, цвет — `grp`. Тип — столбцы с накоплением.
   Сразу видно, на что уходят деньги: товар, маркетинг, логистика, налоги.

5. **Каналы поступлений.** Датасет ДДС, фильтр `section = CFO` и `amount > 0`,
   цвет — `article`. Видно долю ЮKassa, Ozon и прямых оплат.

6. **Таблица ДДС.** Датасет ДДС, сводная таблица: строки — `section` и `article`,
   столбцы — `period_start`, значения — сумма `amount`.

7. **Индикатор «Не разобрано».** Датасет «Денежный поток», показатель
   `unclassified_share_amount` в процентах. Настройте цвет: зелёный до 5%,
   красный выше. Рядом — таблица из датасета «Не разобрано» с колонками
   `operation_date`, `amount`, `counterparty_name`, `purpose`, `issue`.

8. **Контроль сходимости.** Таблица: `period_start` и `check_diff`.
   Все значения должны быть нулями. Если где-то не ноль — смотрите
   [operations.md](operations.md), раздел про `check_diff`.

## Часть 5. Дашборд

Создайте дашборд, положите чарты в таком порядке: сверху KPI-карточки,
под ними FCF по месяцам и водопад, ниже структура расходов и каналы поступлений,
в самом низу таблица ДДС и блок «Не разобрано».

Добавьте два селектора и свяжите их со всеми чартами:

- по полю `period_type` (значения M, Q, Y) — переключение месяц/квартал/год;
- по полю `period_start` — выбор диапазона дат.

Дашборд обновляется автоматически: данные подтягиваются из базы при каждом открытии,
а база пополняется ежедневно в 07:00.

## Если что-то не подключается

- **«Не удалось подключиться»** — проверьте группу безопасности и что в `pg_hba.conf`
  есть строка именно для того диапазона, из которого приходит DataLens.
- **«Аутентификация не пройдена»** — в `pg_hba.conf` должен стоять метод
  `scram-sha-256`, а пароль роли задан именно им.
- **«Отношение не существует»** — датасет смотрит на таблицу вне витрин.
  Роль `datalens_ro` намеренно не видит ничего, кроме пяти представлений.
