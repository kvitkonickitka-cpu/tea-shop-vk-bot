# Как этим пользоваться каждый день

Ничего делать не нужно: в 07:00 по Москве система сама забирает вчерашние операции
и раскладывает их по статьям. Ниже — что делать, когда что-то требует внимания.

## Как добавить правило

Правила лежат в файле `data/rules.csv`. Его можно открыть в Excel, Google Таблицах
или «Numbers» — это обычная таблица.

Одна строка — одно правило. Колонки:

| Колонка | Что писать |
|---|---|
| `priority` | число; правила проверяются по возрастанию, срабатывает первое подошедшее |
| `field` | где искать: `counterparty_inn`, `counterparty_name`, `purpose`, `tbank_category`, `direction`, `account` |
| `match_type` | `equals` — точное совпадение, `contains` — «содержит», `regex` — для сложных случаев |
| `value` | что искать; регистр букв не важен |
| `direction` | `in` (приход), `out` (расход) или пусто (любое) |
| `amount_min`, `amount_max` | ограничение по сумме, можно оставить пустыми |
| `article_id` | код статьи из `data/articles.csv` |
| `active` | `true` — правило работает, `false` — выключено |
| `comment` | пометка для себя |

Самое надёжное правило — по ИНН: название контрагента банк может написать по-разному,
а ИНН не меняется.

После правки:

```bash
cd /opt/cashflow
sudo -u cashflow .venv/bin/python -m cashflow import-rules
sudo -u cashflow .venv/bin/python -m cashflow classify
```

Если в файле ошибка (нет такой статьи, битое выражение), система **ничего не поменяет**
и напишет, в какой строке проблема. Старые правила продолжат работать.

## Как разметить одну операцию вручную

Когда операция разовая и правило под неё писать незачем:

1. Найдите её `operation_id` в дашборде на вкладке «Не разобрано».
2. Допишите строку в `data/manual_overrides.csv`:
   `operation_id,article_id,comment`
3. Выполните `import-rules` и `classify`, как выше.

Ручная разметка сильнее любого правила.

## Откуда берутся предложения правил

```bash
sudo -u cashflow .venv/bin/python -m cashflow suggest-rules
```

Команда смотрит на всё, что не разобралось, группирует по ИНН и по типовым фразам
в назначении платежа и пишет черновик в `data/suggested_rules.csv`, отсортированный
по сумме — сверху то, что сильнее искажает отчёты.

В черновике в колонке `article_id` стоит `ВПИШИТЕ_СТАТЬЮ`, а `active` = `false`.
Впишите статью, поставьте `true` и перенесите строку в `rules.csv`. Файл с черновиком
в репозиторий не попадает.

## Что делать, если check_diff ≠ 0

`check_diff` — это проверка: остаток на конец месяца минус остаток на начало минус
движение денег за месяц. В норме ноль. Если не ноль, деньги где-то потерялись.

Что проверять по порядку:

1. **Все ли счета заведены.** Если операции идут по счёту, которого нет в
   `TBANK_ACCOUNTS`, переводы на него выглядят как исчезновение денег.
   Проверьте: `SELECT DISTINCT account_number FROM finance.raw_operations;`
2. **Прошла ли последняя синхронизация.** `python -m cashflow doctor` покажет
   дату последнего успешного запуска по каждому счёту.
3. **Не пустая ли таблица остатков.** Если банк не присылал остатки,
   `opening_balance` будет пустым, а не нулём — тогда `check_diff` тоже пустой,
   это не ошибка, а отсутствие данных. Запустите `sync` ещё раз.
4. **Не задним ли числом пришла операция.** Банк иногда дописывает операции
   за прошлые дни. Обычная синхронизация перекрывает 10 дней; если операция
   старше, перезалейте период:
   `python -m cashflow backfill --from 2025-01-01`

Если после этого расхождение осталось — сверьте выписку в приложении банка
за этот месяц с таблицей ДДС и напишите, что не сходится.

## Как перевыпустить токен

Токен живёт 90 дней **с момента последнего использования**. Ежедневный запуск
продлевает его сам, так что истечь он может только если система долго стояла.

Если `doctor` пишет, что токен не принят:

1. В кабинете Т-Бизнеса выпустите новый токен с доступом только «Счета и выписки».
2. Укажите тот же статический IP.
3. `sudo nano /etc/cashflow/.env` — замените `TBANK_TOKEN`.
4. `sudo -u cashflow /opt/cashflow/.venv/bin/python -m cashflow doctor`

Старый токен после этого отзовите в кабинете.

## Полезные команды

```bash
cd /opt/cashflow
S=".venv/bin/python -m cashflow"

sudo -u cashflow $S doctor              # всё ли в порядке
sudo -u cashflow $S sync                # забрать свежие операции
sudo -u cashflow $S classify            # разложить по статьям
sudo -u cashflow $S run-all             # всё сразу, то же что по расписанию
sudo -u cashflow $S backfill --from 2024-01-01   # перезалить историю
sudo -u cashflow $S loan-schedule --amount 100000 --rate 27 --months 12 \
                    --first-payment 2025-02-10 --out data/loan_schedule.csv
```

Журнал работы: `tail -50 /var/log/cashflow/cashflow.log`

## Если поменялся кредит

Пересчитайте график и загрузите его:

```bash
sudo -u cashflow .venv/bin/python -m cashflow loan-schedule \
    --amount 100000 --rate 27 --months 12 --first-payment 2025-02-10 \
    --out /opt/cashflow/data/loan_schedule.csv
sudo -u cashflow .venv/bin/python -m cashflow import-rules
sudo -u cashflow .venv/bin/python -m cashflow classify
```

Платёж по кредиту приходит одной суммой, а в отчётах делится: проценты — в
операционный поток, тело долга — в финансовый. Если сумма платежа не совпала
с графиком, операция не угадывается, а попадает в «Не разобрано» с пометкой
`loan_amount_mismatch`.
