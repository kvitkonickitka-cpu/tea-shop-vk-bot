# Отдельный Telegram-аналитик (основа, не развёрнут)

Это отдельный процесс и отдельный Telegram-токен. Он не забирает обновления
Ops/alert-бота, не меняет клиентские диалоги, не запускает миграции магазина.
Основной workflow Timeweb его не запускает. Включение — отдельный этап после PR.

## Поведение

- `/report [1|7|30]`, `/sales [1|7|30]`, `/ads [1|7|30]`: точная сводка за
  завершённые дни МСК; без аргумента — вчера. Эти отчёты не расходуют OpenAI.
- `@логин_бота вопрос`, `/ask вопрос` или ответ на сообщение аналитика:
  диалог через OpenAI Responses API, по умолчанию `gpt-6.1-sol`, effort low.
  Можно уточнять смысл метрик, сравнивать периоды, спрашивать о недостающих данных.
- Доступ **только по chat_id**, без списка пользователей: любой участник
  указанной группы может обращаться к боту. Другие чаты/личка игнорируются.
  Неадресованная переписка не анализируется. Фото/вложения не отправляются модели.
  В канале отчёты можно читать, для вопросов нужна группа (или группа обсуждения,
  её chat_id задаётся в конфигурации); channel_post не обрабатывается.
- `/status`: настройки источников, OpenAI, расписания; `/reset`: сброс своего контекста.
- Контекст уточнений — в памяти, отдельно на участника и тему, до 3 пар реплик,
  30 минут бездействия, максимум 100 сессий; исчезает при рестарте. У анонимных
  администраторов одна идентичность sender_chat, поэтому контекст у них общий.
- Необязательный ежедневный отчёт после 09:00 МСК за вчера. По умолчанию выключен.
  После простоя отправляется только отчёт текущего дня, без многодневного спама.

## Данные и расчёты

Источник рекламы — явная заглушка `UnconnectedAds`, статус `not_connected`.
Не подключаем выдуманные кампании, не считаем отсутствующие расходы нулевыми.
CTR/CPC/CAC/ROAS не считаются до подключения затрат, показов/кликов и атрибуции.

Продажи: опциональный адаптер `PostgresSales`, фиксированный параметризованный
SELECT из `analytics.v_orders`, read-only транзакция, таймаут запроса 10 секунд.
Пустой DSN → «не подключён»; ошибка → «временно недоступен»; успешный запрос без
строк → реальные нули. Тестовые заказы/клиенты исключены самой витриной.
Созданные заказы — по created_date_msk; оплаты — по paid_date_msk. Суммы total
включают доставку и исключают полные возвраты по текущему статусу. Частичные
возвраты отдельно не учтены. Это не бухгалтерская прибыль и не сумма поступлений
на счёт. Сумма / число оплаченных без полного возврата = средняя сумма заказа.
При отсутствии оплат средний чек не определён. Не называем общие продажи рекламными.

OpenAI получает свежий агрегат за вчера и инструмент `get_summary(days,
offset_days)` для 1/7/30 дней, смещение до 365 дней. Нет произвольного SQL,
идентификаторов покупателей, истории заказов или действий записи. Текст вопроса
и цитата ответа очищаются от распознанных телефонов, почт, ссылок, адресов и имён;
это эвристика, а не гарантия удаления любых ПДн — не отправляйте их аналитику.
Telegram user/chat ID используются локально и не включаются в API-запрос.

На вопрос максимум 3 API-вызова, 2000 output tokens на вызов, максимум 2 вызова
инструмента. Весь чат делит лимит 50 вопросов/попыток в сутки МСК. Лимит хранится
на диске; сбой API тоже расходует попытку. В SQLite считаются input/output tokens
по дням (не оценка счёта). `store=false`; reasoning items сохраняются только внутри
хода. Секреты/тексты не логируются. При сбое API остаётся `/report`.

## Настройка после ревью и разрешения на выпуск

1. В BotFather создать отдельного бота; добавить его в нужную группу.
   Privacy Mode можно оставить включённым: использовать упоминание, команду
   с именем бота или ответ на сообщение бота. Дать право отправлять сообщения.
2. В `deploy/timeweb/analytics-bot/` скопировать `env.example` в
   `.env.analytics-bot`, права 600. Заполнить токен и отрицательный chat_id группы.
   Не использовать токен alert/Ops. Не копировать весь `.env.bot`.
3. Для Timeweb задать существующий разрешённый Aeza Telegram endpoint и
   proxy secret. Для OpenAI — серверный API-ключ, OpenAI base URL прокси и
   отдельный OpenAI proxy secret. Значения не коммитить и не присылать в чат.
   Подписка локального Codex к этому сервису не относится.
4. Пока продаж нет, DSN можно оставить пустым. Позже создать отдельную роль
   только с CONNECT к нужной БД, USAGE на analytics, SELECT на analytics.v_orders.
   Не давать доступ к pii_vault или рабочим таблицам; применять SSL и пароль роли.
   Не использовать роль приложения с правами записи.
5. Только после разрешённого выпуска:
   `docker compose -f deploy/timeweb/analytics-bot/compose.yml up -d --build`.
   Порты не публикуются; SQLite хранится в отдельном named volume.
6. Проверить `/status`, `/report`, упоминание и уточнение ответом на сообщение.
   Из другого чата ответов быть не должно. Затем включить daily_enabled при необходимости.

SQLite хранит offset Telegram, дневные отметки отправки и счётчики API, без текстов.
Процесс захватывает file lock: на один volume допускается один экземпляр.
Между успешной отправкой Telegram и записью отметки возможен аварийный разрыв;
после него повтор сообщения возможен (Telegram не даёт ключ идемпотентности).
Не запускать два экземпляра с разными volumes и одним токеном.

## Проверки

`tests/test_analytics_bot.py`: реальная тестовая БД, даты МСК, исключение тестов
и возвратов, отсутствие данных/ошибка/ноль, доступ всех участников только нужной
группы, упоминания и ответы, запрет фона, расписание и повтор после сбоя,
реальный OpenAI SDK на MockTransport, цикл инструментов, метки и лимиты.
Полный suite запускается по общему регламенту перед коммитом и PR.

Схема Responses/function calling сверена с официальной документацией:
https://developers.openai.com/api/docs/guides/function-calling
